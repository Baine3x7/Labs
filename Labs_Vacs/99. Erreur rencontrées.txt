# Récapitulatif — Erreurs rencontrées & questions posées

**Script principal concerné** : `1.4.1_Create_Users.ps1` (import CSV → création de comptes AD)

---

## 1. Erreurs rencontrées

### 1.1 `MissingPropertyName`

**Message** :
```
Missing property name after reference operator.
FullyQualifiedErrorId : MissingPropertyName
```

**Cause** : le script a été lancé sans préfixe `.\` devant son nom. PowerShell n'exécute jamais un script du dossier courant sans ce préfixe (contrairement à `cmd.exe`), et interprète le nom tapé comme une expression (`1.4.1` est lu comme un nombre suivi d'un point, d'où l'erreur).

**Solution** :
```powershell
.\1.4.1_Create_Users.ps1
```

---

### 1.2 `AmpersandNotAllowed`

**Message** :
```
powershell.exe -ExecutionPolicy bypass & ".\1.4.1_Create_Users.ps1"
The ampersand (&) character is not allowed. The & operator is reserved for future use...
```

**Cause** : l'opérateur `&` doit être seul en tête de commande, pas combiné après d'autres arguments.

**Solution** :
```powershell
powershell.exe -ExecutionPolicy bypass ".\1.4.1_Create_Users.ps1"
```
(pas besoin de `&` ici, le script est déjà passé en argument)

---

### 1.3 `FileNotFoundException` (Import-Csv)

**Message** :
```
Import-Csv : Could not find file 'C:\Users\Administrator\Desktop\Temp\4.2_utilisateurs.csv'.
```

**Cause** : le chemin défini dans `$CheminCSV` ne correspondait pas au nom réel du fichier présent dans le dossier.

**Solution** : vérification avec
```powershell
Get-ChildItem C:\Users\Administrator\Desktop\Temp\*.csv
```
puis correction du chemin, avant remplacement par une détection dynamique du fichier (voir Q17).

---

### 1.4 `ADIdentityNotFoundException` (Get-ADUser / OU)

**Message** :
```
Get-ADUser : Directory object not found
```

**Cause** : `$OU_Cible = "OU=Utilisateurs,DC=home,DC=lan"` ne correspondait à aucune OU existante. Seule l'OU par défaut "Domain Controllers" existait.

**Solution** :
```powershell
New-ADOrganizationalUnit -Name "Utilisateurs" -Path "DC=home,DC=lan"
```

Vérifications utiles :
```powershell
Get-ADDomain | Select-Object DistinguishedName
Get-ADOrganizationalUnit -Filter * | Select-Object Name, DistinguishedName
```

---

### 1.5 `InvokeMethodOnNull` (`$u.Nom.Trim()`)

**Message** :
```
You cannot call a method on a null-valued expression.
At ...1.4.1_Create_Users.ps1:38 char:5
+     $Nom     = $u.Nom.Trim()
```

**Cause** : mauvaise correspondance entre le délimiteur utilisé dans `Import-Csv` (`;`) et le délimiteur réel du fichier CSV (`,`). Le CSV entier était donc lu comme une seule colonne, et la propriété `Nom` n'existait pas sur l'objet importé.

**Vérification** :
```powershell
Get-Content .\1.4.2_utilisateurs.csv -TotalCount 3
```
→ a révélé un fichier au format :
```
Nom,Prenom,Service
Baine,Tech,"Domain Admins; Tech; Dir"
```

**Solution** : inversion des deux séparateurs dans le script :
- `$SeparateurGroupes = ";"` (séparateur **DANS** la colonne Service)
- `Import-Csv -Delimiter ","` (séparateur **ENTRE** les colonnes)

**Remarque annexe** : problème d'encodage observé en parallèle (accents affichés `Ã©` au lieu de `é`) dans les messages `Write-Warning`/`Write-Host`.

## 2. Questions posées et réponses

| Q1 | Comment importer un CSV (`Nom;Prenom;Service`) et créer automatiquement les comptes + les ajouter au bon groupe selon le service ? | Script utilisant `Import-Csv` avec délimiteur `;`, puis `New-ADUser` pour créer chaque compte (login = initiale prénom + nom), et `Get-ADGroup`/`Add-ADGroupMember` pour l'ajout au groupe correspondant (création automatique du groupe s'il n'existait pas). |
| Q2 | Comment permettre qu'un utilisateur appartienne à plusieurs groupes ? | Découpage de la colonne Service avec `.Split()` sur un séparateur dédié (`$SeparateurGroupes`), puis boucle `foreach` sur chaque groupe obtenu pour l'ajout individuel de l'utilisateur. |
| Q3 | Fusion de la version personnalisée du script (paramètres `home.lan` / `Pa$$w0rd`) avec la version multi-groupes. | Réinjection des valeurs personnalisées (OU, domaine, mot de passe) dans la version multi-groupes, avec remarque sur le `$` dans les chaînes entre guillemets doubles (nécessite des guillemets simples pour être pris littéralement). |
| Q4 | Test de robustesse du script sur des cas limites (service vide, doublons, espaces mal placés, collisions de login). | Identification de 2 trous : service vide (compte créé sans groupe, sans avertissement) et collision de login (deux utilisateurs différents générant le même SamAccountName). ## 3. Erreurs supplémentaires — script `1.8_Desactivation de compte.ps1`

### 3.1 Erreurs de parsing en cascade (encodage)

**Message (extraits)** :
```
Unexpected token '}' in expression or statement.
Unexpected token 'inactif' in expression or statement.
Unexpected token 'Rapport' in expression or statement.
The string is missing the terminator: ".
Missing closing '}' in statement block or type definition.
The Try statement is missing its Catch or Finally block.
```

**Cause** : le fichier était encodé dans un format que PowerShell interprétait mal (caractères accentués corrompus, ex: `DÃ©sactiver`, `exportÃ©`, `â€”`), ce qui cassait le parsing des chaînes de caractères contenant des accents et provoquait une cascade d'erreurs de syntaxe sans rapport apparent avec la vraie cause.

**Solution** : réécriture du fichier en UTF-8 propre :
```powershell
$Contenu = Get-Content ".\1.8_Desactivation de compte.ps1" -Raw -Encoding UTF8
Set-Content ".\1.8_Desactivation de compte.ps1" -Value $Contenu -Encoding UTF8
```
→ changer l'encodage du fichier a résolu la cascade d'erreurs.

### 3.2 `CommandNotFoundException` (nom de fichier avec espaces)

**Message** :
```
PS> powershell.exe -ExecutionPolicy Bypass "./1.8_Desactivation de compte.ps1"
./1.8_Desactivation : The term './1.8_Desactivation' is not recognized as the name of a cmdlet, function, script file, or operable program.
```

**Cause** : le nom de fichier contient des espaces (`1.8_Desactivation de compte.ps1`). Sans guillemets correctement positionnés autour du **chemin complet**, PowerShell/cmd découpe la commande au premier espace et ne reconnaît que `./1.8_Desactivation` comme nom de commande.

**Solution retenue** : renommer le fichier pour supprimer les espaces plutôt que jongler avec les guillemets à chaque appel :
```powershell
Rename-Item ".\1.8_Desactivation de compte.ps1" ".\1.8_Desactivation_de_compte.ps1"
```

## Enseignements transversaux

- **Toujours préfixer `.\`** pour exécuter un script du dossier courant en PowerShell — sinon le nom est interprété comme une expression.
- **`&` doit être seul en tête de commande** — inutile si le script est déjà passé en argument à `powershell.exe`.
- **Vérifier le nom réel des fichiers** (`Get-ChildItem`) avant de coder un chemin en dur — préférer une détection dynamique par mot-clé.
- **Le délimiteur CSV et le séparateur interne d'une colonne multi-valeurs doivent être différents** — sinon le fichier devient ambigu à parser.
- **Un problème d'encodage peut se manifester comme des erreurs de syntaxe sans rapport apparent** — si les erreurs semblent incohérentes avec le code visible, vérifier l'encodage du fichier en premier.
- **Éviter les espaces dans les noms de fichiers de script** — source classique d'erreurs `CommandNotFoundException` à l'exécution.
- **`-PasswordNeverExpires` et `-ChangePasswordAtLogon` sont incompatibles ensemble à la création** — les appliquer en deux temps (création, puis `Set-ADUser`).
