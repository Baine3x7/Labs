# Tutoriel : Déploiement avec OSDCloud (successeur "spirituel" de MDT)

## 1. Principe

**OSDCloud** est un module PowerShell open-source (par David Segura) qui permet de créer un environnement **WinPE personnalisé** capable de télécharger et déployer une image Windows directement depuis Internet ou depuis un partage réseau — sans dépendre de MDT ni de SCCM.

Contrairement à MDT (interface graphique, Task Sequences, Deployment Share), OSDCloud est **100% scripté en PowerShell**, ce qui correspond bien à ton profil (tu es déjà à l'aise avec l'automatisation PowerShell pour ton labo).

Le principe général :
1. On construit une image WinPE custom contenant le module OSDCloud
2. On la boot (clé USB, ISO, ou PXE via WDS)
3. Un script PowerShell (`OSDCloud.ps1` ou custom) s'exécute automatiquement pour partitionner, télécharger l'image Windows, l'appliquer, injecter les pilotes et lancer les post-configurations

---

## 2. Prérequis

| Composant | Rôle |
|---|---|
| Windows 10/11 ou Windows Server (poste de build) | Pour créer le média WinPE |
| **Windows ADK + WinPE add-on** | Toujours nécessaire (OSDCloud s'appuie dessus) |
| PowerShell 5.1 (pas Core) | Pour l'exécution des cmdlets OSDCloud |
| Connexion Internet sur le poste de build ET idéalement sur les machines cibles | OSDCloud télécharge souvent l'image Windows à la volée |

---

## 3. Installer le module OSDCloud

Sur ton poste d'administration (avec ADK déjà installé) :

```powershell
Install-Module OSD -Force
Import-Module OSD -Force
```

Vérifier la version :
```powershell
Get-Module OSD -ListAvailable
```

---

## 4. Créer le média de démarrage WinPE OSDCloud

### 4.1 Générer le template WinPE

```powershell
New-OSDCloudTemplate
```

Cette commande télécharge les composants ADK/WinPE nécessaires et prépare un template réutilisable.

### 4.2 Créer l'espace de travail (workspace)

```powershell
New-OSDCloudWorkspace -WorkspacePath "C:\OSDCloud"
```

### 4.3 (Optionnel) Personnaliser le WinPE

On peut injecter des pilotes réseau/stockage spécifiques, ou un script de démarrage automatique :

```powershell
Edit-OSDCloudWinPE -CloudDriver *
```

`-CloudDriver *` intègre les pilotes réseau/stockage génériques pour la plupart des machines physiques et virtuelles.

### 4.4 Générer l'ISO ou la clé USB bootable

```powershell
# Générer une ISO bootable
New-OSDCloudISO

# OU préparer une clé USB directement
New-OSDCloudUSB
```

L'ISO générée se trouve dans `C:\OSDCloud\Media`.

---

## 5. Déploiement (boot sur la machine cible)

1. Démarrer la machine cible sur l'ISO/clé USB OSDCloud (ou via PXE, voir section 7)
2. Le WinPE custom se charge, une fenêtre PowerShell s'ouvre automatiquement
3. Lancer la commande de déploiement (si non automatisée dans le média) :

```powershell
Start-OSDCloud -OSVersion 'Windows 11' -OSBuild '24H2' -OSEdition 'Pro' -OSLanguage 'fr-fr'
```

OSDCloud va alors :
- Partitionner le disque
- Télécharger l'image Windows correspondante (via Microsoft ou un cache local si configuré)
- Appliquer l'image
- Injecter les pilotes détectés
- Redémarrer

---

## 6. Automatiser complètement (façon "Lite Touch")

Pour éviter de taper la commande manuellement à chaque déploiement, on peut créer un script `autounattend` ou injecter directement le script de démarrage dans le WinPE :

```powershell
# Dans le workspace OSDCloud, éditer Startup.ps1 pour y intégrer :
Start-OSDCloud -OSVersion 'Windows 11' -OSBuild '24H2' -OSEdition 'Pro' -OSLanguage 'fr-fr' -ZTI
```

Le paramètre `-ZTI` (Zero Touch Installation) supprime les invites interactives — le déploiement se lance automatiquement au boot.

### 6.1 Jonction au domaine post-déploiement

OSDCloud ne gère pas nativement la jonction de domaine comme MDT. On l'ajoute généralement via un script exécuté au premier logon (tâche planifiée ou `Register-ScheduledTask`) qui appelle :

```powershell
Add-Computer -DomainName "home.lan" -OUPath "OU=OU_Computers,DC=home,DC=lan" `
  -Credential (Get-Credential) -Restart
```

Ce script peut être placé dans le dossier `Automate` du workspace OSDCloud pour être embarqué automatiquement dans le WinPE et copié sur le disque cible avant le premier démarrage.

---

## 7. Déploiement réseau (PXE) avec WDS

OSDCloud peut aussi être diffusé en PXE, en réutilisant **WDS** comme simple serveur de boot (WDS reste utile même sans MDT) :

```powershell
Import-WdsBootImage -Path "C:\OSDCloud\Media\Sources\boot.wim" -NewImageName "OSDCloud Boot"
```

Le client boot en PXE sur WDS, récupère le WinPE OSDCloud, puis le script de déploiement s'exécute comme en boot USB/ISO.

---

## 8. Comparatif rapide avec MDT

| Fonctionnalité | MDT | OSDCloud |
|---|---|---|
| Interface | Graphique (Deployment Workbench) | 100% PowerShell |
| Source de l'image OS | Deployment Share local | Téléchargement direct (ou cache local possible) |
| Injection pilotes | Dossier "Out-of-Box Drivers" | `-CloudDriver` ou pilotes custom dans le workspace |
| Jonction domaine | Intégrée (CustomSettings.ini) | À scripter manuellement (post-install) |
| Maintenance/support | ❌ Retiré (janvier 2026) | ✅ Activement maintenu, open-source |
| Courbe d'apprentissage | Moyenne (interface + fichiers ini) | Plus élevée si peu familier avec PowerShell, mais naturelle si déjà à l'aise en script |

---

## 9. Bonnes pratiques

- **Tester d'abord en VM** (Hyper-V ou VMware) avant tout déploiement physique
- **Mettre en cache les images Windows en local** si la bande passante Internet est limitée, via `Save-OSDCloudISO` ou un partage réseau custom, pour éviter de re-télécharger à chaque déploiement
- **Versionner tes scripts d'automatisation** (jonction domaine, post-config) dans le dossier `Automate` du workspace
- Consulter la documentation officielle du projet (`osdcloud.com` / dépôt GitHub `OSDeploy/OSD`) pour les mises à jour de cmdlets, le projet évoluant régulièrement
